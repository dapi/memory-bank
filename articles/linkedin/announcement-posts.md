# Короткие LinkedIn-посты для анонса статей

## 1. Оркестрация и «бесконечная» сессия

Когда AI-агент работает над задачей несколько часов или дней, хочется просто дать ему больше контекста.

Но длинный чат — плохое долговременное хранилище. Решения теряются среди старых сообщений, ограничения забываются, а после сбоя работу трудно воспроизвести.

Я всё больше прихожу к другой модели:

```text
короткие сессии
+ долговечное состояние задачи
+ проверяемые handoff-контракты
+ воспроизводимые доказательства
= непрерывный агентный процесс
```

То есть сессия может закончиться. Задача — нет.

В новой статье разобрал:

- что хранить вместо полного чата;
- чем цифровая роль отличается от «персонажа агента»;
- почему workflow важнее одного большого промпта;
- как начать с Git и файлов, не внедряя сразу Temporal;
- какие переходы стоит проверять детерминированно.

## 2. Code Property Graph

`grep` может найти функцию `process_payment`. Но он не ответит:

- кто её вызывает;
- откуда приходят данные;
- при каких условиях выполняется вызов;
- какие модули затронет изменение;
- может ли пользовательский ввод дойти до опасной операции.

Для этого нужны отношения, а не только текстовые совпадения.

В новой статье простыми словами разобрал пять представлений кода:

```text
AST              — из чего состоит код
CFG              — как идёт выполнение
Call graph       — кто кого вызывает
Data flow        — куда движутся значения
Dependency graph — от чего зависит компонент
```

Code Property Graph связывает их в одну модель и позволяет задавать составные вопросы ко всему репозиторию.

Для AI-агентов это особенно интересно: статический анализ находит воспроизводимый путь, LLM объясняет его и предлагает изменение, а повторный анализ и тесты подтверждают результат.
